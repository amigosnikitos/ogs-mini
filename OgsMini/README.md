# OGS Mini — простой клиент online-go.com для Android

Kotlin + Jetpack Compose. Вход через OAuth2, список ваших партий, игра на доске, подсчёт, открытые вызовы и создание партий.

## Что умеет

- Вход через браузер (OAuth2 Authorization Code + PKCE) или запасной вход по логину/паролю.
- Список активных партий с пометкой «Ваш ход».
- Открыть любую партию по номеру (чужую — в режиме наблюдения).
- Игра: тап по пересечению → «Подтвердить», «Пас», «Сдаться». Проверяются занятая точка, ко и самоубийство.
- Подсчёт: тап по группе отмечает её мёртвой, «Принять» подтверждает результат.
- Realtime-соединение с автопереподключением, часы (приблизительные).
- **Открытые вызовы** (как «Available games» на сайте): живой список с вкладками «Быстрые» и «Заочные», фильтры
  (рейтинговые, размеры доски, фора, недоступные по рангу), подробности вызова и кнопка «Принять игру».
  Свои вызовы подсвечены, их можно снять.
- **Создание вызова**: размер доски, скорость и система времени (Фишер, бёёми, канадская, простая, абсолютная) с теми же
  вариантами, что на сайте, рейтинговая или дружеская, фора, коми, правила, цвет, анализ, ограничение по рангу.
  Вызов можно адресовать конкретному игроку по имени. Последняя форма запоминается.
- **Ожидание соперника** для быстрых партий: пока экран открыт, приложение раз в секунду подтверждает серверу, что
  вызов жив, и открывает партию, как только соперник принял вызов; вызов можно отменить. Заочные вызовы просто
  появляются в списке.
- Ошибки сервера (метод, адрес, код и начало ответа) показываются на экране целиком.

Партии с форой (в том числе со свободной расстановкой) разбираются по правилам движка OGS.

Пока нет: автоподбор соперника (automatch), входящие вызовы и их принятие/отклонение, командные (рэнго) вызовы,
чат, отмена хода, разбор партий, уведомления.

## Запуск

1. Зарегистрируйте своё приложение на <https://online-go.com/oauth2/applications/>:
   - **Client type**: Public
   - **Authorization grant type**: Authorization code
   - **Redirect URIs**: `gobo://callback`

   Скопируйте Client ID. Секрет не нужен.
2. Откройте папку проекта в Android Studio (нужен JDK 17+) и дождитесь синхронизации Gradle.
   Версии зафиксированы: AGP 8.7.3, Kotlin 2.0.21, Gradle 8.9. Если Studio предложит обновить — можно согласиться.
3. Запустите на устройстве или эмуляторе с Android 8.0+.
4. В приложении вставьте Client ID и нажмите «Войти через браузер».

Вход по паролю работает, только если сервер разрешил вашему приложению grant `password`. Если такого варианта в форме регистрации нет — используйте вход через браузер.

Юнит-тесты логики (без эмулятора): `./gradlew :core:test`.

## Как получить APK

- **Android Studio**: меню Build → Build Bundle(s) / APK(s) → Build APK(s). Файл появится в `app/build/outputs/apk/debug/app-debug.apk`.
- **Командная строка** (нужен установленный Android SDK): `./gradlew :app:assembleDebug`.
- **Без установки Android Studio**: репозиторий на GitHub сам собирает debug-APK при каждом пуше (`.github/workflows/build.yml`, при необходимости вручную: Actions → Build APK → Run workflow). Перед сборкой запускаются юнит-тесты `:core`. Готовый файл появляется в Releases (тег `latest`, `app-debug.apk`).

APK подписывается постоянным ключом `app/debug.keystore`. Он лежит в репозитории открыто (приложение личное), зато новые версии ставятся поверх старых. Версию 0.1 (с другим, случайным ключом) нужно один раз удалить перед установкой 0.2.

Чтобы поставить APK на телефон, разрешите установку из неизвестных источников для приложения, через которое открываете файл.

## Что проверено

- `:core` (доска, захваты, ко, самоубийство, разбор сообщений OGS, состояние партии, очерёдность ходов и фора, PKCE по вектору из RFC 7636, список вызовов, форма создания, время и ранги): **53 теста проходят**, их же запускает GitHub Actions перед каждой сборкой.
- Сборка APK проходит в GitHub Actions. На телефоне автора проверены вход через браузер, открытие партии и ход.

## Что проверено не полностью

- Сервер OGS из среды, где писался код, недоступен, поэтому поведение живого сервера проверяется только на телефоне. Протокол realtime-API в документации описан скупо:
  - адрес WebSocket неоднозначен — клиент перебирает `wss://wsp.online-go.com`, `wss://online-go.com/ws`, `wss://online-go.com/socket`;
  - чей ход и какого цвета камень, считается только по списку ходов, начальному игроку и форе (как в официальном клиенте OGS), а не по сообщениям о часах: сервер может прислать их раньше самого хода;
  - нумерация ходов (`move_number`) проверяется терпимо, при расхождении состояние запрашивается заново;
  - расстановка в партиях с фиксированной форой берётся из `initial_state`, если сервер её прислал;
  - формат часов поддержан только для вариантов с `thinking_time`;
  - вызовы: адреса и сообщения взяты из исходников сайта, но принимает ли сервер OAuth-токен на `POST /api/v1/challenges`,
    `/challenges/<id>/accept` и `DELETE /challenges/<id>`, проверяется только на телефоне. Если сервер откажет,
    ошибка покажется на экране.

Если что-то не работает, смотрите Logcat с тегом `OgsMini`.

## Устройство

```
core/   чистый Kotlin, без Android: GoBoard, GameSession, Wire (JSON-сообщения), Pkce, Coord
app/    Android: AppViewModel, Store, net/OgsApi (REST), net/OgsSocket (WebSocket), ui/* (Compose)
```

Используемые адреса: `/oauth2/authorize/`, `/oauth2/token/`, `GET /api/v1/ui/config` (поле `user_jwt`),
`GET /api/v1/ui/overview` (`active_games`). Сообщения WebSocket — JSON-массивы `[команда, данные]`:
`authenticate`, `net/ping`, `game/connect`, `game/move` (`"dd"`, пас — `".."`), `game/resign`,
`game/removed_stones/set|accept`; события `game/<id>/gamedata|move|clock|phase|removed_stones`.

Вызовы: подписка `seek_graph/connect {channel:"global"}` и события `seekgraph/global` (добавление, `delete`, `game_started`);
создание — `POST /api/v1/challenges` или `POST /api/v1/players/<id>/challenge`, поиск игрока — `GET /api/v1/players?username=`,
принятие — `POST /api/v1/challenges/<id>/accept`, отмена — `DELETE /api/v1/challenges/<id>` (запасной адрес
`/api/v1/me/challenges/<id>`). Быстрый вызов после создания держится сообщением `challenge/keepalive` раз в секунду;
начало партии — событие `game/<id>/gamedata`, отказ соперника — уведомление `gameOfferRejected`.

Документация OGS: <https://docs.online-go.com>
